# Демонстрация работодателю — 7–10 минут

## Подготовка

Установить зависимости и Chromium по README, настроить свой provider. Для текущей демонстрации предпочтителен официальный GigaChat: `LLM_PROVIDER=gigachat`, `LLM_MODEL=GigaChat-3-Ultra`, локальный `GIGACHAT_AUTH_KEY`. Сначала показать `python main.py --check-llm`, затем browser smoke. Не показывать содержимое `.env` на записи. Security baseline до provider-патча: 197 passed, 1 skipped. Текущая Termux/GigaChat ревизия: **145 passed, 18 skipped, 0 failed**; `--check-browser` PASS, `--check-llm` PASS и автономный Wikipedia E2E с GigaChat-3-Ultra — live PASS. Новые демонстрационные сценарии фиксировать только по фактическому прогону.

В отдельном терминале:

```powershell
.\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory tests/fixtures
```

В терминале агента:

```powershell
$env:BROWSER_BACKEND = "playwright"
$env:HEADLESS = "false"
$env:CONFIRMATION_MODE = "risky"
$env:MAX_AGENT_STEPS = "100"
```


Если хотите показать attachment на локальном тестовом/разрешённом сайте, заранее задайте `BROWSER_UPLOAD_ROOT` на отдельную папку с тестовым файлом. Не указывайте корень домашнего диска.

## 1. Корзина и verification

```powershell
.\.venv\Scripts\python.exe main.py --task "Открой http://127.0.0.1:8765/. В магазине добавь 2 синих блокнота, бюджет 30 EUR. Проверь товар, цвет, количество и итоговую сумму в корзине. Дойди до оформления и остановись перед оплатой."
```

Показать свежие observations, select/quantity, expected_outcome и verify_action; итог должен быть 24 EUR. Подтверждать только понятные действия, оплату не разрешать. Это тестовый сайт; цифры — проверяемое ожидание стенда, не ответ, зашитый в агента.

## 2. Почта: сначала анализ, затем approval

```powershell
.\.venv\Scripts\python.exe main.py --task "Открой http://127.0.0.1:8765/ и раздел Почта. Прочитай 10 писем. Сначала перечисли очевидный спам с причинами, не изменяя письма. Запроси подтверждение на перемещение этих писем в Спам. После разрешения выполни действие и проверь список и количество."
```

На стенде подозрительны письма 4 и 8. Показать read-only анализ/remember и confirmation. Один кандидат можно отклонить: он не должен быть обработан или объявлен обработанным. При обоих разрешениях во входящих останется 8.
На длинной ленте отдельно показать `extract_collection`: он должен вернуть компактные строки писем и refs controls, не выполняя мутаций.

## 3. Вакансии и индивидуальные письма

```powershell
.\.venv\Scripts\python.exe main.py --task "Открой http://127.0.0.1:8765/, раздел Вакансии. Изучи резюме. Сравни все вакансии и выбери 3 подходящие AI-позиции. Не выдумывай опыт. Подготовь индивидуальные сопроводительные письма, отправляй каждое только после подтверждения и проверяй receipt каждого отклика."
```

Показать план, keyed facts о профиле/вакансиях, различающиеся письма, подтверждения и проверку результата. Несоответствующая senior Java позиция должна быть исключена.
Для списка вакансий удобно показать `extract_collection`, а для открытой карточки — `extract_page`; никаких HH-specific tools в production-коде нет.

## 4. Универсальность и реальная авторизация

Если время позволяет, выполнить задачу о факте на Wikipedia через видимый поиск без изменения кода. Затем показать CDP attach к отдельному Chrome profile с уже выполненным ручным login. Для реальной почты безопасно сначала ограничиться чтением. Дальнейшие действия — по `ACCEPTANCE.md`.

Формулировка на защите: «Production агент принимает решения через LLM; в коде нет маршрутов под эти сайты. Автотесты проверяют механизмы отдельно от качества модели. Live результат этой демонстрации фиксируется по факту; заранее PASS не заявляется».

Wikipedia/GigaChat live E2E уже подтверждён на текущей Termux-ревизии. Сценарии магазина, почты и вакансий с реальной LLM считаются **UNVERIFIED**, пока не выполнены отдельно. Если provider/сеть/challenge не позволяют продолжить, показать точный blocked и не подменять LLM заранее написанным сценарием.
